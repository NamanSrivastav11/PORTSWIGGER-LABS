## Lab Description & Observations


- User roles are enforced via a client-controlled request parameter
- Role validation is not enforced server-side
- Administrative functionality exists for privileged users
- Known credentials: `wiener:peter`

Goal: Escalate privileges to access the admin interface and delete the user `carlos`.


------------------------------------------------

The application differentiates users based on a role value sent with the HTTP requests.
Instead of deriving authorization from a server-side session or access control list, the backend trusts a parameter supplied by the client.

The design allows direct manipulation of privilege levels by modifying requests.

## Result

-----------------------------------------------------------


## Impact


- Unauthorized privilege escalation

- Full administrative access

- Potential for data manipulation and account compromise



--------------------------------------------------------------


## Root Cause

- Trusting client-side parameters for authorization decisions

- Absence of server-side role validation

- No seperation between user input and access control logic


------------------------------------------------------------


## Security Takeaway

Authorization decisions must never rely on client-controlled input
User roles must be enforced exclusively on the server using trusted session data.
