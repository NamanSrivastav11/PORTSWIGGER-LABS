## LAB: Unprotected admin functionality with unpredictable URL


- Reference: [Access Control](https://portswigger.net/web-security/access-control)



## Lab Description & Observations


- Administrative interface exists but is not listed anywhere
- The admin URL is intended to be "unpredictable"
- No authentication or authorization checks are enforced
  

**Goal**: Discover the hidden admin endpoint and perform an administrative action.


------------------------------------------------

Unlike the first access control lab, the admin panel is not exposed via `robots.txt`. This suggests that the application ries on the secrecy of the URL itself as a security control.



------------------------------------------------------



## Enumeration


Viewing the source of the home page reveals a JavaScript snippet containing a reference to an admin path: `/admin-lip7ti`


<img width="1644" height="994" alt="image" src="https://github.com/user-attachments/assets/77acde8f-a415-4311-93ec-9920707f90b1" />



## Exploitation

1. Copy the discovered admin path from the page source.


2. Navigate dirctly to the URL: `https://0a5700cf03f2e64380579406007800cc.web-security-academy.net/admin-lip7ti`


3. The admin panel loads without authentication.


   <img width="1447" height="440" alt="image" src="https://github.com/user-attachments/assets/8624acdc-338c-4ae6-8901-0b2394cac55b" />


4. Access the user management section.


5. **Delete** the user `carlos`



<img width="1444" height="550" alt="image" src="https://github.com/user-attachments/assets/eef59363-70fa-471d-a05f-76ad37772cf5" />



----------------------------------------------------------------


## Result


- The administrative action is executed successfully

- Once the user `carlos` is deleted, the lab is marked as solved.


-----------------------------------------------------------------


## Impact


- Administrative access exposed to unauthenticated users

- User accounts can be deleted or modified

- Full compromise of application integrity



-----------------------------------------------------------------


## Root Cause


- No authentication enforcement on admin endpoints

- No authorization checks for privileged actions

- Full compromise of application integrity


------------------------------------------------------------------


## Security Takeaway

Unpredictible URLs do not provide access control.
Any privileged endpoint must enforce authentication and authorization in the server, regardless of how difficult it is to guess.
