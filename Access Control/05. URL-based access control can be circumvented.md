## Lab Description & Observations


- Application uses URL-based restrictions to protect admin functionality
- Access control enforced only on specific paths
- Inconsistent or incomplete authorization checks

Goal: Bypass URL-based access control; access the admin panel and delete the user `carlos`


------------------------------------------------

## Analysis

The application demonstrates a common access control -> **authorization decision based solely on URL paths**

The application blocks direct access to `/admin` but fails to apply the same authorization logic to all equivalent or related endpoints.
Alternative URLs expose protected functionality.



------------------------------------------------------



## Authentication





After authentication, normal user functionality is available, but no admin features are visible in the UI.
