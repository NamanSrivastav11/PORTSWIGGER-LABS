## Lab Description & Observations


- Administrative functionality is expsoed
- No authentication or authorization checks are enforced

Goal: Identify the unprotected admin interface and use it to delete the user `carlos`.


------------------------------------------------

The lab uses a simple blog-style website. No admin links or privileged functionality are visible in the UI, which suggests that sensitive endpoints may exist but are hidden rather than protected.

## Enumeration


Accessing the following endpoint: `/robots.txt`


> _Robots.txt_ is a simple text file that instructs web crawlers about which parts of a website are open for indexing and which should remain off-limits.
> located in a website's root directory, guides search engine crawlers on what to index and what to ignore.



<img width="663" height="109" alt="image" src="https://github.com/user-attachments/assets/8286b9ff-6409-4402-9313-fe06e2db6b37" />


This indicates the existence of an administrative endpoint that the application does not want indexed by search engines. However, `robots.txt` does not enforce access control and only provides guidance to crawlers.

## Impact

- Full administrative access without credentials.
- Unauthorized user deletion.
- Potential for data loss, privilege escalation, and complete application takeover.


-------------------------------------------------------------

## Root Cause

- Missing authentication cheks on sensitive endpoints.
- No role-based authorization validation
- Reliance on obscurity instead of security controls.


-------------------------------------------------------------


## Security Takeaway

Administrative functionality must always be protected server-side.

Any endpoint that can be accessed directly must be treated as exposed and secured accordingly.
