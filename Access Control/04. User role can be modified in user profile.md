## Lab Description & Observations


- User roles are enforced via a client-controlled reqiest parameter
- Role validation is not enforced server-side
- Administrative functionality exists for privileged users
- Known credentials: `wiener:peter`

Goal: Excalate privileges to acces the admin interface and delete the user `carlos`.


------------------------------------------------

## Analysis

The application differentiates users based on a role value with HTTP requests. Instead of deriving authorization from a server-side session or access control list, the backend trusts a parameter supplied by the client.

This design allows direct manipulation of privilege levels by modifying requests.

## Request Inspection

A parameter controlling authorization ('roleid') is present



### Modify the role parameter


Change the role value to the `roleid=2` and add the following to the request:

```
"email":"test@test.com",
"username":"wiener3",
"apikey": "goKJrLM88d2ImlQdLc8NjCcLSqKU4p57",
"roleid": 2
```


<img width="1920" height="1152" alt="image" src="https://github.com/user-attachments/assets/44cbb247-69c3-475b-b24d-21292888db56" />


Forward the request to the server.


No errors are returned; the server accepts the modification
This confirms the backend does not validate role changes.
