## Lab Description

This lab implements a login workflow where authentication outcomes are reflected with slightly different error messages depending on which validation step fails.

The backend first determines whether the submitted username exists, and only then verifies the password for known accounts, because those two failure points return different response content, the application leaks account-existence information before successful authentication.

----------------

### Reference: https://portswigger.net/web-security/authentication

--------------

## Analysis

A secure login endpoint should return a single generic failure response for all invalid credential combination.
In this lab, the response is not normalized across failure paths. When a nonexistent username is submitted, the server returns one message, and when a valid username is paired with an invalid password, the server returns a different message.

This behavioral difference is enough to convert this login endpoint into an account enumeration entry point.
