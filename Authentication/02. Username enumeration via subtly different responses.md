# Lab: Username enumeration via subtly different responses

<img width="915" height="387" alt="image" src="https://github.com/user-attachments/assets/9633120b-bb28-400d-8862-e861cd57e64b" />

## Lab Description

The application implements a login mechanism where authentication feedback is not uniform across failure scenarios. Internally, the server processes username validation and password verification as two distinct stages, and the response generated depends on which stage fails. 


------------

### Reference : https://portswigger.net/web-security/authentication

------------

## Steps

1. The login request is intercepted using Burp Proxy and forwarded to Burp Intruder.

   <img width="1687" height="985" alt="image" src="https://github.com/user-attachments/assets/25202896-7dff-4f17-8dcb-2bbe4bb6f3fa" />

2. Select the `username` and `password` parameter as the injection points.

   <img width="1131" height="448" alt="image" src="https://github.com/user-attachments/assets/20d6df4e-875b-42ab-9dbc-8604f97e9bd6" />

3. Select the attack type as `Cluster Bomb Attack` and now we can simultaneously give two runtime files to be used for the two parameters for brute forcing; once the files have been loaded into the Intruder, start the attack.

5. On the Options tab, inder Grep - Extract, type `Invalid username and password` and click `Add`.

   <img width="522" height="476" alt="image" src="https://github.com/user-attachments/assets/0a275946-ef4f-44d7-95ed-000d8fbd3e84" />

Once the attack is finished, notice that there is an additional column as `Invalid username and password`.
Sort the results using this column and we can notice that one of the responses was different. The request received was a `302` response. 

<img width="1712" height="1073" alt="image" src="https://github.com/user-attachments/assets/07f5b328-fdea-4741-803d-c74551ff6dfa" />

Now, try to login using this username and password.

<img width="768" height="343" alt="image" src="https://github.com/user-attachments/assets/70131ff2-0a99-4f23-a3eb-f72b44e70b33" />

Once you have logged in using these credentials, the lab is marked is solved.
