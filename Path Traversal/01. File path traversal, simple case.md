## SOLUTION

---------------------------------------------

- Reference: https://portswigger.net/web-security/file-path-traversal

---------------------------------------------

The lab contains a path traversal vulnerability in the endpoint that serves product images.
The image filename parameter is used directly in a filesystem path, so traversal sequences can escape the intended directory

---------------------------------------------------

## Steps

We can start by exploring the application and navigating to any product page and view the page source of any of the products.


<img width="1508" height="1004" alt="image" src="https://github.com/user-attachments/assets/ca2db3ae-9b98-414c-a1cc-d2c26ad32364" />

It can be observed that the product images are given as explicit file names in URL arguments to `/image`.

<img width="519" height="110" alt="image" src="https://github.com/user-attachments/assets/8e7c97c9-6769-47d1-9643-006373b1e805" />

Now, we can test for some basic traversal payloads; send the request to **Burp Repeater** and replace the `filename` with:

```
../../../etc/passwd
```

<img width="1920" height="1116" alt="image" src="https://github.com/user-attachments/assets/c7d381b4-d65a-438f-a881-e07956f78a70" />

The response body includes standard `etc/passwd` entries and for this lab reading the `etc/passwd` marks the lab as solved.
