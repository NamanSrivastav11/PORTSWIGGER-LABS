## Analysis

The image retrieval functionality takes a `filename` parameter and resolves it to a filesystem path of the backend.
In this lab, traversal sequences are not accepted in their plain form because the application attempts to sanitize user input.

But the sanitization is performed at the wrong stage of input processing. The request value is URL-decoded by the web server layer and later URL-decoded again by the application code, which means the value is transformed twice before reaching the filesystem API. 

-> In this lab, a standard payload such as `../../../etc/passwd` fails because the filter directly sees `../` sequence and strips them before path resolution. A once-encoded traversal payload such as `%2e%2e%2f` may also fail, because after the server-level decode it already appears as `../`, and the filter removes it.

The logic flaw appears when traversal is encoded one layer deeper so that the first decode does not produce `../` yet.
At that point, the filter does not detect traversal sequences, but the second decode inside application code converts the remaining encoded tokens into active traversal sequences.
