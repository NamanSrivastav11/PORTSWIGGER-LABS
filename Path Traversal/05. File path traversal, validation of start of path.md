## Lab Description

This lab exposes an image-loading endpoint that accepts a user-controlled filename and then enforces access control by checking whether the resulting string starts with an expected base directory.

The defensive check is conceptually "prefix-based allowlisting", where any path begining with `/var/www/images` is considered safe.

This induces a weakness that the application validates the prefix before doing any canonicalization, so the path can still contain traversal segments that escape the trusted directory after resolution.


---------------------------------------------

- Reference: https://portswigger.net/web-security/file-path-traversal
  
---------------------------------------------

## Analysis

The lab validates user input by checking whether the supplied path starts with an expected image directory prefix. The control is intended to prevent arbritrary file reads by constraining requests to a trusted base path.

So, the vulnerability exists because the application does not sanitize or strip `../` sequences that appear **after** the validated prefix. This ultimately allows us to satisfy the start-of-path validation and subsequently traverse out of the base directory.

## Steps

Start by intercepting a request for opening an image inside Burp Suite. 

<img width="1162" height="268" alt="image" src="https://github.com/user-attachments/assets/d07bdec5-ebab-47e7-b124-21aff413b3e2" />

Send this intercepted request to Burp Repeater; locate the `filename` parameter within the GET request string.

<img width="1687" height="1014" alt="image" src="https://github.com/user-attachments/assets/68dd99b7-8aa0-48f5-930a-da3af6917def" />

**Payload Construction:**

```text
/var/www/images/../../../etc/passwd
```

**Transformation flow:**

Input: `/var/www/images/../../../etc/passwd`  
After application prefix validation: accepted, because it starts with `/var/www/images/`  
After filesystem normalization: `/etc/passwd`  
Final resolved path: `/etc/passwd`

Now replace the `filename` parameter with our crafted payload.
As the request is processed, the application performs the start-of-path check and accepts the input. 

<img width="1920" height="1119" alt="image" src="https://github.com/user-attachments/assets/38fd3433-ceea-419c-8f5e-a20099824c88" />

The response now returns `passwd` enteries, hence confirming that the bypass is confirmed.
Once the enteries are displayed, the lab is marked as complete.
