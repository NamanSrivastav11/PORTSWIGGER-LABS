## Lab Description and Observations

- Product stock checker takes `productId` and `storeId` from the user.
- Backend executes an OS command that includes these parameters and returns the raw output.
- Inputs are concatenated directly ubto the shell command with no sanitization.

- Goal: exploit command injection to run `whoami` and retrieve the system user name.

-------------------------------------------------

The Lab uses the familiar shop application. On a product page, there is a **Check stock** feature that takes a store from a dropdown and displays the current stock level.

<img width="936" height="985" alt="image" src="https://github.com/user-attachments/assets/f2795bb9-6e77-497f-b3ca-eb77d363a372" />

Capturing the request in Burp Suite - 

<img width="1002" height="327" alt="image" src="https://github.com/user-attachments/assets/8f72a131-5d86-4acd-aad5-4a03bfc15535" />

The server responds with a number (e.g., 72) representing the stock count, but the lab description tells us that this number is actually the raw output of an underlying OS command.

A simplified backend pattern might be:

```
echo system("stockreport.sh " .
  $_POST['productId']."".
  $_POST['storeId']);
```

This means user-controlled values end up inside a shell command strnig, which is a prime candidate for command injection using separators such as `;`, `&&`. `|`, or `&`.

To find the injection point and separator, the request us sent to Burp Repeater and each parameter is tested with the OS metacharacters and simple proof-of-concept commands.

-----------------------------------------------
