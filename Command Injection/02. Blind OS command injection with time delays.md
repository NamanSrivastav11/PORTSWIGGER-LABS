## Lab Description and Observations

- Feedback form (`/feedback`) takes `name`, `email`, `subject`, and `message`.
- Server executes an OS command that includes these user-supplied valuables.
- Command output is **not** returned in the HTTP response -> blind command injection.
- Goal: exploit the blind OS command injection vulnerability to cause a **10 second delay** in the server's response.

-------------------------------------------------

The Lab uses a blog site. At the top navigation bar there is a **Submit feedback** link that leads to a fomr with the following fields:

- Name
- Email
- Subject
- Message

Submitting normal feedback generates a `POS /feedback` request:

<img width="1045" height="370" alt="image" src="https://github.com/user-attachments/assets/c360787d-0813-44d9-9247-a71f2aa68209" />

Because the output is not visible, this is a **blind OS command injection** scenario. Instead of looking for direct command output, the idea is to use a command that introduces a **time delay** and infer successful injection from the slow HTTP response.

Command options on Unix-like systems:

- `ping -c 10 127.0.0.1` -> pings loopback 10 times (~10 seconds)
- `sleep 10` -> directly sleeps for 10 seconds.

------------------------------------------------------

## Finding the injectable parameter

The request is sent to Burp Repeater, and each parameter is tested with a time-delay payload.

<img width="751" height="333" alt="image" src="https://github.com/user-attachments/assets/1834e23c-c311-4f17-bb26-d39db1492ee6" />

Starting from the `email` parameter.

PAYLOAD: `email=test@test.com||ping+-c+10+127.0.0.1||`

Full request -> 

<img width="753" height="344" alt="image" src="https://github.com/user-attachments/assets/fe6b9d56-23fb-4d63-a71c-3e7bb235078f" />

> `||` is a shell operator: "execute right-hand command if left-hand command fails"
> 
> If the original command part involving `email` fails or returns non-zero, `ping -c 10 127.0.0.1` will run.
> 
> `+` in the payload is interpreted as a space in URL-encoded form, so the actual shell command becomes `ping -c 10 127.0.0.1`.

When this request is sent, the response takes **~10 seconds** to arrive instead of responding immediately.

<img width="1611" height="1052" alt="image" src="https://github.com/user-attachments/assets/7b422f8d-f5b3-45b4-a43a-4d1d0019dd46" />

This strongly indicates that the injected `ping` command executed on the server and waited for 10 ICMP packets on loopback.

If there were no command injection, the response time would remain roughly constant regardless of the payload. Here, the timing change is the side-channel providing the existence of blind OS command injection.
