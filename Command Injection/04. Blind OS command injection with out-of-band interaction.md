## Lab Description and Observations

- Feedback function (`/feedback`) has a blind OS command injection vulnerability.
- The application executes a shell command containing user-supplied details from the feedback form.
- Command is executed **aynchronously** and has no visible impact on the HTTP response.
- We **cannot** redirect output to any location we can read.
- However, **out-of-band (OAST)** interactions (e.g., DNS) can be triggered with an external domain.


Goal: exploit the vulnerability so the server perform a DNS lookup to Burp Collaborator (or equivalent OAST server), providing command execution.

------------------------------------------------

The lab uses a blog application with a **Submit feedback** page that has a form with:
- Name
- Email
- Subject
- Message

The response is a generic "Thank you" page with no trace of any command output.
The lab description clarifies that:
> 1. The application executes a shell command containing these user inputs.
> 2. The command is executed asynchronously and **does not affect** the response.
> 3. It is not pssible to redirect output somewhere we can reach.
> 4. We can however, trigger out-of-band interactions with an external domain.

Because there is no visible output and no writable web-accessible directory, our only signal for successful injection is an **external network interaction** (e.g., DNS lookup to a domain we control).
